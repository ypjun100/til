# 컨피그맵

```
kubectl create configmap log-level-cm --from-literal LOG_LEVEL=DEBUG
```

- 일반적인 설정값을 담아 저장할 수 있는 쿠버네티스 오브젝트이며, 네임스페이스별로 컨피그맵이 존재함
- 컨피그맵은 YAML 파일이나 `kubectl create configmap` 명령어를 사용해 생성할 수 있음
	- 위 예시 명령어는 `LOG_LEVEL`이 `DEBUG`인 `log-level-cm` 컨피그맵을 생성하는 명령어임
	- `--from-literal` 옵션을 여러 번 사용하여 여러 개의 키-값을 설정할 수 있음
- 컨피그맵에 저장된 설정값은 `kubectl describe configmap` 명령어로 확인할 수 있음

```yml
# log-level-cm 컨피그맵
LOG_LEVEL: DEBUG

# 파드 YAML 파일에 컨피그맵 정의
spec:
	containers:
	- name: my-webserver
	  env:
		  valueFrom:
			  configMapKeyRef:
				  name: log-level-cm
				  key: LOG_LEVEL
```

- 컨피그맵을 파드에서 사용하는 방법은 두 가지로, 설정값을 앱이 어떻게 읽는지에 따라 방법을 선택해야 함

### 컨피그맵의 값을 컨테이너의 환경 변수로 사용

- 개발자가 설정한 컨피그맵의 값을 파드의 컨테이너 환경 변수로 가져오는 방식임
- 컨피그맵에 저장된 키-값 데이터가 그대로 컨테이너의 환경 변수의 키-값으로 사용됨
- 앱이 시스템 환경 변수로부터 설정값을 가져온다면 해당 방법을 적용할 수 있음

### 컨피그맵의 값을 파드 내부의 파일로 마운트해 사용

- 개발자가 설정한 컨피그맵의 값을 파드 컨테이너 내부의 특정 파일로 마운트하는 방식임
- 컨피그맵의 값을 특정 파일로 마운트하면, 해당 파일의 내용으로 해당 컨피그맵의 키-값에서 '값'이 저장됨
	- `LOG_LEVEL=INFO`를 `/config/level`로 마운트하면, 해당 파일에는 `INFO` 값이 저장됨
- 앱이 `nginx.conf` 등의 파일을 통해 설정값을 읽는다면 해당 방법을 적용할 수 있음
