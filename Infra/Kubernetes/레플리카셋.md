# 레플리카셋

- 여러 파드를 생성하기 위해 하나의 YAML 내에서 '---' 구분자로 사용하여 여러 파드를 정의할 수 있음
	- 하지만 동일한 파드 개수가 많아질수록 일일이 정의하는 것을 비효율적인 작업임
- 또한, 파드가 삭제되거나, 파드가 위치한 노드에 장애가 발생하면 직접 재생성하지 않는 한 복구되지 않음
- 쿠버네티스에서 파드만 정의해 사용하는 경우는 없으며, 이 한계점을 해결하는 레플리카셋을 함께 사용함

### 레플리카셋 사용하기

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: replicatset-nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-nginx-pods-label
  template:
    metadata:
      name: my-nginx-pod
      labels:
        app: my-nginx-pods-label
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
```

- 레플리카셋은 정해진 수의 동일한 파드가 항상 실행되도록 정의하며, 이를 기반으로 쿠버네티스가 관리함
- 노드 장애 등의 이유로 파드를 사용할 수 없다면, 다른 노드에서 동일한 파드를 다시 생성함
- `spec.replicas`: 동일한 파드를 몇 개 유지시킬 것인지 설정함
- `spec.template`: 파드를 생성할 때 사용할 템플릿을 정의함

### 레플리카셋의 동작 원리

- 레플리카셋은 마치 파드와 연결된 것처럼 보이나, 연결되어 있지 않고 느슨한 연결을 유지하고 있음
	- 이러한 느슨한 연결은 파드와 레플리카셋의 정의 중 라벨 셀렉터를 이용해 이뤄짐
- 라벨은 리소스의 부가적인 정보를 표현할 때나 서로 다른 오브젝트를 찾기 위해 사용되는 메타데이터임
