# 파드

- 파드는 쿠버네티스에서 사용되는 컨테이너 애플리케이션의 기본 단위이며, 1개 이상의 컨테이너 집합임
	- 1개의 파드에는 1개의 컨테이너가 존재할 수도 있고, 여러 개의 컨테이너가 존재할 수도 있음
- 도커 엔진에서는 기본 단위가 컨테이너였고, 스웜 모드에서는 서비스, 쿠버네티스에서는 파드임

```
apiVersion: v1
kind: Pod
metadata:
  name: my-nginx-pod
spec:
  containers:
  - name: my-nginx-container
    image: nginx:latest
    ports:
    - containerPort: 80
      protocol: TCP
```

- 쿠버네티스의 YAML 파일은 일반적으로 `apiVersion`, `kind`, `metadata`, `spec`으로 구성됨
	- `apiVersion`: YAML 파일에서 정의한 오브젝트의 API 버전을 타타냄
	- `kind`: 이 리소스의 종류를 나타냄. 해당 항목에 사용할 수 있는 종류는 `kubectl api-resources` 명령어의 KIND 항목에서 확인 가능함
	- `metadata`: 라벨, 주석, 이름 등과 같은 리소스의 부가 정보를 입력함
	- `spec`: 리소스를 생성하기 위한 자세한 정보를 입력함
- 작성한 YAML 파일은 `kubectl apply -f` 명령어로 쿠버네티스에 생성할 수 있음
	- `kubectl get <오브젝트 이름>`을 사용하면 특정 오브젝트의 목록 확인 가능
	- 위에서 생성한 Pod 오브젝트의 목록을 보려면 `kubectl get pods`를 사용함
	- 생성된 리소스의 자세한 정보는 `kubectl describe pods <파드 이름>`을 사용함
	- 파드의 컨테이너 내부로 접속하기 위해서는 도커와 동일하게 `kubectl exec` 명령어 사용 가능
	- 파드 컨테이너가 발생한 표준 출력 로그도 도커와 동일하게 `kubectl logs` 명령어를 사용함
- 쿠버네티스 오브젝트는 `kubectl delete` 명령어로 삭제할 수 있음

> [!QUESTION] 쿠버네티스에서 도커 컨테이너가 아닌 파드라는 개념을 사용하는 이유
> 파드는 컨테이너 위에 논리적 호스트 역할을 하는 추가 추상화 계층으로, 여러 컨테이너를 하나의 배포·관리 단위로 묶기 위해 도입되었다. 특히 아래와 같은 공유 리소스를 안전하게 운용할 수 있다.
> - 네트워크 네임스페이스 : 같은 파드의 컨테이너들은 하나의 IP와 포트 공간을 공유해 `localhost`로 서로 통신이 가능함
> - 스토리지(볼륨) : 여러 컨테이너가 같은 볼륨을 마운트해 파일을 주고받을 수 있음
> - 라이프사이클 : 함께 생성되고 함께 종료/재시작됨
