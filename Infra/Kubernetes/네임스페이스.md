# 네임스페이스

- 용도에 따라 컨테이너와 그에 관련된 리소스들을 구분 지어 관리할 수 있는 논리적인 가상 그룹 오브젝트
	- 하나의 네임스페이스 안에는 파드, 레플리카셋, 디플로이먼트, 서비스 등과 같은 리소스들이 묶임

### 네임스페이스 기본 개념 이해

```
k get namespaces
NAME              STATUS   AGE
default           Active   26d
kube-node-lease   Active   26d
kube-public       Active   26d
kube-system       Active   26d
```

- 네임스페이스 목록은 `k get namespace`로 확인할 수 있으며, 기본적으로 4개의 네임스페이스가 존재함
	- `kubectl get pods --namespace default`로 네임스페이스 내 생성된 파드 확인 가능
- `default` 네임스페이스는 쿠버네티스 설치 시 자동으로 사용하도록 설정되는 네임스페이스임
	- `kubectl` 명령어로 쿠버네티스 리소스를 사용할 때는 기본적으로 `default` 네임스페이스를 사용함
- `kube-system`은 클러스터 구성에 필수적인 컴포넌트들과 설정값 등이 존재하는 네임스페이스임

### 네임스페이스 사용하기

```
apiVersion: v1
kind: Namespace
metadata:
  name: production
```

- YAML 파일로 네임스페이스를 생성하려면 `kubectl apply -f 파일명`을 실행하여 생성함
	- 또는 `kubectl create namespace 네임스페이스명`으로 직접 생성 가능
- 특정 네임스페이스에 리소스를 생성하려면 리소스 YAML 파일의 `metadata.namespace`를 설정하면 됨

### 네임스페이스의 서비스에 접근하기

```shell
# 다른 네임스페이스 내의 파드에서 아래와 같이 실행 가능
curl hostname-svc-clusterip-ns.production.svc:8080
```

- 기본적으로 같은 네임스페이스 내의 서비스에 접근할 때에는 서비스 이름만으로 접속할 수 있음
	- 따라서 기존 방식 그대로 다른 네임스페이스의 서비스로는 접근할 수 없음
- 다른 네임스페이스의 서비스에 접근하려면 `{서비스 이름}.{네임스페이스 이름}.svc`와 같이 접속해야 함
- 위 예시는 production 네임스페이스에 있는 특정 서비스에 접속하는 과정임
