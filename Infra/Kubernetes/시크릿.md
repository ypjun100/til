# 시크릿

- 시크릿은 SSH 키, 비밀번호와 같은 민감한 정보를 저장하기 위한 네임스페이스에 종속되는 오브젝트임
- 시크릿은 컨피그맵 처럼 문자열 값 등을 똑같이 저장 가능하며, 저장된 값을 파드에 제공할 수도 있음
	- 대신에 민감한 정보 저장을 위해 컨피그맵보다 좀 더 세분화된 사용 방법을 제공함

```
$ kubectl create secret generic my-password --from-literal password=1234
```

- 컨피그맵처럼 `--from-file`이나 `--from-env-file` 옵션을 이용해 파일로부터 값을 읽을 수 있음

```
$ kubectl get secret my-password -o yaml
apiVersion: v1
data:
  password: MTIzNA==
kind: Secret
...
type: Opaque
```

- `kubectl get` 명령어로 시크릿의 정보를 확인 가능하며, 시크릿의 값은 base64로 인코딩하여 저장함
- 시크릿 값을 base64로 저장하는 건 암호화가 아닌, 바이너리 데이터를 YAML에서 안전하게 다루기 위함임
- 시크릿의 보안은 RBAC를 통한 접근 제한, Pod에 필요한 시크릿만 제공 등의 방법을 통해 제공됨

```
apiVersion: v1
kind: Pod
metadata:
  name: secret-env-example
spec:
  containers:
    - name: my-container
      image: busybox
      args: ['tail', '-f', '/dev/null']
      envFrom:
      - secretRef:
          name: my-password
```

- 시크릿은 컨피그맵과 비슷하게 데이터를 환경 변수로 설정하거나 특정 경로의 파일로 마운트할 수도 있음
- 시크릿은 base64로 저장되지만, 파드에서 시크릿을 가져오면 base64로 디코딩된 원래 값을 사용하게 됨

> [!Question] 컨피그맵과 시크릿의 차이점
> base64는 디코딩이 가능하기에 값을 읽을 권한이 있는 사람에게는 컨피그맵과 마찬가지로 값을 볼 수 있다. 그렇지만 컨피그맵과 구분하는 이유는 값을 다루는 방식과 적용할 수 있는 보호 조치에 있다.
> 
> - 컨피그맵은 공개되어도 되는 설정값용으로 로그 레벨과 같은 정보를 저장하기 위해 사용된다.
> - 시크릿은 비밀번호 · 토큰 · 개인 키처럼 노출되면 안 되는 값을 저장하기 위해 사용되며, 단순히 시크릿으로만 저장한다고 안전해지지는 않고 특정 유저만 시크릿에 접근 가능하도록 RBAC 권한을 따로 제한하던지 등의 방법을 사용해야 한다.
