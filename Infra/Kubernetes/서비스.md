# 서비스

- 파드의 IP는 영속적이지 않아 여러 개의 디플로이먼트를 연동하려면 파드 IP가 아닌 다른 방법이 필요함
	- 도커에서는 컨테이너 간의 연동을 위해 `-p` 옵션이나 `--link` 옵션을 사용하여 연동했음
	- YAML에서 설정하는 `containerPort`는 외부 노출 목적이 아닌, 메타데이터 역할임
- 서비스는 파드에 접근하기 위한 규칙을 정의하며, 핵심 기능은 다음과 같음
	- 여러 개의 파드에 쉽게 접근 가능하도록 고유한 도메인 이름을 부여함
	- 여러 개의 파드에 접근할 때 요청을 분산하는 로드 밸런서 기능을 수행함
	- 클라우드 플랫폼의 로드 밸런서, 클러스터 노드의 포트 등을 통해 파드를 외부로 노출함
- 서비스의 종류에 따라 접근 방법이 달라지기 때문에 목적에 맞는 적절한 서비스 종류를 선택해야 함
	- Cluster IP 타입 : 쿠버네티스 내부에서만 파드에 접근할 때 사용 (외부 접근 비허용)
	- NodePort 타입 : 파드의 접근 포트를 클러스터의 모든 노드에 동일하게 개방 (외부 접근 허용)
	- LoadBalancer 타입 : 클라우드 플랫폼에서 제공하는 로드 밸런서를 동적으로 프로비저닝해 파드에 연결 (외부 접근 허용)

### ClusterIP 타입 서비스

- 쿠버네티스 서비스의 기본 타입으로, 클러스터 내부에서만 접근 가능한 가상 IP를 할당받는 방식
- Pod는 재생성될 때마다 IP가 바뀌지만, ClusterIP는 고정된 주소를 제공해 클라이언트의 안정적 접근 제공
- 쿠버네티스 DNS는 서비스 이름으로 조회하면, IP를 응답해주기에 IP 대신에 서비스 이름으로 통신 가능

```
apiVersion: v1
kind: Service
metadata:
  name: hostname-svc-clusterip
spec:
  ports:
    - name: web-port
      port: 8080
      targetPort: 80
  selector:
    app: webserver
  type: ClusterIP
```

- `spec.selector` : 서비스에서 어떤 라벨을 가지는 파드에 접근할 수 있게 만들 건지 결정함
- `spec.ports.port` : 생성된 서비스는 쿠버네티스 내에서만 사용 가능한 고유 IP를 할당 받음. `port` 항목에는 서비스의 IP에 접근할 때 사용할 포트를 설정함
- `spec.ports.targetPort` : `selector` 항목에서 타겟팅한 파드들이 내부적으로 사용하고 있는 포트
- `spec.type` : 이 서비스가 어떤 타입인지를 나타냄

- 아래 과정은 ClusterIP 타입의 서비스를 생성하는 과정임

1. 특정 라벨을 가지는 파드를 서비스와 연결하기 위해 서비스의 YAML 파일에 `selector` 항목을 정의함
2. 파드에 접근할 때 사용하는 포트(`containerPort`)를 YAML 파일의 `targetPort`에 정의함
3. 서비스 YAML 파일의 `port`에 `8080`을 명시해 `{IP}:8080` 으로 접근할 수 있게 설정함
4. ClusterIP 타입의 서비스가 생성되면, 서비스는 쿠버네티스 클러스터 내에서만 사용 가능한 IP를 할당받음
5. 쿠버네티스 클러스터에서 서비스의 내부 IP 또는 서비스 이름으로 파드에 접근 가능함

> [!INFORMATION] ClusterIP에서 'Cluster'의 의미
> ClusterIP가 할당받는 IP는 어느 특정 노드에 속한 IP가 아니라 클러스터 전체 네트워크 공간에 유효한 주소이다. 따라서, ClusterIP라는 이름은 문자 그대로 "클러스터 범위의 가상 IP를 할당한다"는 동작 방식을 그대로 서술한 것이다.

### NodePort 타입 서비스

```
apiVersion: v1
kind: Service
metadata:
  name: hostname-svc-nodeport
spec:
  ports:
    - name: web-port
      port: 8080
      targetPort: 80
  selector:
    app: webserver
  type: NodePort
```

- ClusterIP 서비스는 내부 접근만 가능하지만, NodePort 타입 서비스는 클러스터 외부에서도 접근 가능함
- NodePort 타입의 서비스는 모든 노드의 특정 포트를 개방해 서비스에 접근하는 방식임
- YAML 파일에 정의하는 라벨 셀렉터, 포트 설정 등과 같은 부분들은 ClusterIP의 설정과 동일함

![](https://user-images.githubusercontent.com/47745785/138993288-350f1f56-75fd-45f9-9690-1803fb4287e2.png)

- NodePort 타입 서비스 생성 시 ClusterIP 타입과 동일하게 클러스터 내에서 접근 가능한 가상 IP가 발급됨
	- 클러스터 내 어떤 노드든지 해당 가상 IP를 통해서 서비스에 접근 가능함
	- 이는 NodePort 타입의 서비스가 ClusterIP의 기능을 포함하고 있기 때문임
- NodePort로는 포트 번호 설정, SSL 인증서 적용 등은 어렵기 때문에 운영 환경에서는 자주 사용되지 않음
- 보통의 경우에는 NodePort 서비스를 외부로 제공하기 보다는 인그레스 오브젝트를 사용하는 경우가 많음
